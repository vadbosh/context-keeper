# context-keeper

**Сохраняет точное состояние сессии Claude Code при сжатии контекста.**

English version: [README.md](README.md).

Чем длиннее сессия, тем дороже каждый ход: весь контекст перечитывается заново.
Если сжимать контекст раньше, ход становится дешевле, но пересказ теряет детали.
Из него пропадает, какие файлы изменены, что закоммичено, а что нет, точные
слова последних запросов и что ещё не доделано.

context-keeper берёт эти факты не из пересказа, а с машины. Перед сжатием он
записывает их в файл-снимок, а сразу после сжатия возвращает снимок модели. Тогда
пересказу остаётся передать только ход рассуждений.

## Что устанавливается

| Часть | Где | Что делает |
|---|---|---|
| `context-keeper` | `~/.local/bin` | команда, которую запускают все три хука |
| хук PreCompact | `~/.claude/settings.json` | `context-keeper snapshot` записывает снимок |
| хук SessionStart с matcher `compact` | `~/.claude/settings.json` | `context-keeper restore` возвращает снимок модели |
| хук SessionStart с matcher `resume` | `~/.claude/settings.json` | `context-keeper resume` читает текущее состояние, когда к сессии возвращаются |
| `autoCompactWindow: 400000` | `~/.claude/settings.json` | на 400 тыс. токенов пользователю предлагают сжать контекст, а не у самой границы окна |
| правило | `~/.claude/rules/context-keeper.md` | говорит пересказу, что сохранить: задачу, решения, точные пути и id, недоделанное |

Если `autoCompactWindow` уже задан, его значение не меняется.

## Кто решает, когда сжимать

Решает пользователь. Когда контекст доходит до окна, Claude Code запускает
автоматическое сжатие, а хук PreCompact его блокирует и печатает:

```text
context-keeper: the context reached the auto-compact threshold. Auto-compaction
is off: run /compact when ready, or /compact <what to keep> to steer the summary.
```

Сессия продолжается без сжатия, пока пользователь не запустит `/compact`: он
проходит как обычно, со снимком. `/compact <что сохранить>` говорит пересказу,
что важно в этот раз. На следующих ходах Claude Code пробует снова: строка
показывается один раз, а следующие попытки блокируются молча, пока
пользователь не сожмёт контекст. За окном место ещё есть:
собственный предел модели выше, например 1 млн токенов при окне в 400 тыс.

Чтобы Claude Code сжимал контекст сам, установите с `--allow-auto`; повторный
запуск без флага снова это выключает.

## Что входит в снимок

- файлы, изменённые в сессии, последние — в конце;
- для каждого затронутого git-репозитория — строка ветки, незакоммиченные
  изменения и пять последних коммитов;
- самая новая заметка `kind: state` из `kb/` этих репозиториев;
- открытые находки сессии, если есть команда `findings`;
- шесть последних запросов, набранных пользователем, дословно.

Снимки лежат в `~/.local/state/context-keeper`, по одному на сессию, хранятся 20
последних. Права каталога — 700, каждого файла — 600: в снимке слова самого
пользователя. Если установлен `secrets-redact` (из env2hell), снимок проходит
через него до записи.

Оба хука SessionStart ещё печатают одну строку для пользователя, например
`context-keeper: snapshot restored — 120 lines, 6740 bytes`.

## Возврат к сессии

Разговор не может знать, что происходило, пока в нём никого не было. Когда к
сессии возвращаются (`claude --resume`, `claude --continue`),
`context-keeper resume` читает состояние на этот момент и передаёт модели:

- время последней активности в сессии и сколько с тех пор прошло;
- для каждого затронутого git-репозитория — строку ветки, незакоммиченные
  изменения и коммиты, сделанные после последней активности;
- чистый репозиторий без новых коммитов занимает одну строку.

Сжималась сессия или нет, неважно: команда читает транскрипт и репозитории, а
не снимок. Пользователь видит одну строку, например
`context-keeper: away 2d 3h; state of 3 repositories read now, 2 new commits`.
На диск ничего не пишется.

## Место на диске

Объём ограничен, следить за ним не нужно. Хранится не больше 20 снимков, каждый
не больше 24000 байт, и по 3 копии каждого файла, который менял установщик.
`~/.local/state/context-keeper` и `~/.local/state/context-keeper-backups`
можно удалить в любой момент. Снимок нужен только с начала сжатия
до нового старта сессии: после этого он уже записан в транскрипт.

## Установка

```bash
./install.sh                 # установить или обновить
./install.sh --dry-run       # показать, что изменится
./install.sh --window 300000 # другое окно сжатия, от 100000 до 1000000
./install.sh --allow-auto    # разрешить Claude Code сжимать самому на окне
./install.sh --uninstall     # убрать хуки, правило и команду
```

После установки перезапустите Claude Code: хуки читаются при старте. Файл,
который предстоит изменить, сначала копируется в
`~/.local/state/context-keeper-backups`, для каждого файла хранятся три
последние копии. В конце установщик проверяет себя: записывает снимок
выдуманной сессии и читает его обратно.

Посмотреть снимок вручную:

```bash
context-keeper show            # самый новый
context-keeper show <session>  # снимок одной сессии
```

## Чего он не делает

- **Не управляет содержанием пересказа.** Хук PreCompact в Claude Code может
  только разрешить или запретить сжатие. Указания для пересказа даёт правило, и
  оно одинаково для всех сессий.
- **Не сжимает часть разговора.** Это делает `/rewind` с пунктом
  *Summarize up to here*, и только интерактивно.
- **Codex и Opencode пока не подключены.** У Codex есть
  `model_auto_compact_token_limit` и `compact_prompt`, у Opencode — плагин-хук
  `experimental.session.compacting`. Оба подключим, когда их хуки будут
  проверены на живой установке.
